# 证据纪律细则

这个文件是 `SKILL.md` 铁律的展开。Phase 1/2 之前读一遍，Phase 5 自检时再读一遍。

---

## 1. 什么算"来源"

| 算 | 不算 |
|---|---|
| arXiv abs 页（`arxiv.org/abs/...`） | "arXiv 上有一篇讲这个的" |
| DOI 解析页（`doi.org/10.xxxx/...`） | 只有作者名和年份，没有链接 |
| 会议官方 proceedings 页 / OpenReview 页 | 二手博客转述的论文结论 |
| 官方代码仓库（github.com/org/repo） | 搜索结果摘要里的一句话 |
| 权威榜单页（paperswithcode 类、官方 leaderboard） | 模型自己"记得"的数字 |
| 教材/课程官方页 | 论坛回答 |

**判据**：把这个 URL 交给一个陌生人，他点开后能不能亲眼看到这条断言？不能，就不算来源。

## 2. 四种标注

- `[已核实]` — 有一个独立来源直接支持，且核验者亲自打开过
- `[多源]` — ≥2 个互相独立的来源支持
- `[单源]` — 只有一个来源，且没有第二个来源能旁证
- **`[不可比]`** — 有来源，但**与其他来源的口径不可通约**（不同标定方法、不同实验条件、
  不同指标定义）。写数字时必须一起写出"在什么条件下、用什么方法量的"

**注意**：`[多源]` 不要求核验阶段判定，只要正文里挂了两个真正独立的 URL 即可。
但**同一个仓库的 README 和它的 wiki 不算两个来源**。

**为什么要有 `[不可比]`**：这是最容易漏、也最要命的一态。
真实案例——三篇论文都报"厘米级分辨率"，但标定方法、目标复杂度、气象条件全不同。
这不是冲突（没人错），也不是确认（数字不能互证），而是**"看起来有共识、实际不可比"**。
不标它，用户会拿"A 比 B 好"去写论文，然后被审稿人打掉。

## 3. 核验者的自我约束（写进提示词里）

核验者的价值全部来自"它没有见过草稿的推理过程"。一旦它开始顺着草稿的思路补充细节，
它就退化成第二个幻觉源。所以核验提示词必须包含：

> 你没有见过任何先前的结论。
> 不要因为草稿给了来源就相信它——自己去打开那个来源，或另找来源。
> evidence 必须是你自己找到的 URL。找不到就留空。
> 不要推断。找不到就说找不到。这一条的使命是挡住幻觉，不是凑数。

**反例**（会让核验失效的写法，别这么写）：

- ❌ "请确认下面这条是否正确：<条目>" → 模型倾向说"正确"
- ❌ "先看草稿的来源，再判断" → 锚定效应
- ✅ "下面这条的真伪未知，请独立检索判定"

## 4. 四态判定标准

| 判定 | 含义 | 处置 |
|---|---|---|
| `confirmed` | 找到独立来源，存在且描述基本准确 | 进正文，标 `[已核实]` |
| `unconfirmed` | 检索不到，但**不能断定不存在**（可能只是检索词不对） | 进 `06-待核实区.md`，附检索词与日期 |
| `contradicted` | 来源之间冲突，或有明确反对证据 | 正文并列两种说法，各挂来源 |
| **`incomparable`** | 各有独立来源，但**口径不可通约** | 正文照写，标 `[不可比]`，写清差在哪 |

**判 `incomparable` 的三个信号**（任一出现就该考虑）：
1. 同一个指标名，但各文的**定义/计算公式**不同
2. 数字相近或都"优于"，但**实验条件/样品/标定方法**不可比较
3. 存在多个互不承认的**评价体系**（如"MTF 判据" vs "可分辨间距" vs "PSNR"）

**绝对禁止**把 `unconfirmed` 写成"不存在"。检索不到 ≠ 不存在，这是两回事。
也禁止把 `incomparable` 硬排成"谁更好"——那不是判断，是编造比较基准。

## 5. 特别容易出幻觉的六类断言

写报告时对这几类加倍小心，它们在文献核验中失败率最高：

1. **数据集规模**（"包含 100 万条样本"）—— 数字经常被记错一个量级
2. **SOTA 数字与提升幅度**（"提升了 3.2 个点"）—— 换一个 benchmark split 就不同
3. **参数量与计算量**（"7B / 训练用了 2000 张 A100"）—— 常把不同版本混起来
4. **作者与机构归属**（"某某团队提出的"）—— 一作、通讯、机构经常张冠李戴
5. **会议年份**（"NeurIPS 2023"）—— arXiv 首发年份 ≠ 正式发表年份
6. **"首次提出"类断言** —— 除非综述明确这么写，否则一定有人更早

对这六类，要求**两个独立来源**，或者明确标注为单一来源的待核实。

## 6. 事实与分析的分离

报告里两类句子必须能一眼分开：

- **事实句** → 必须挂来源，标 `[已核实]`/`[多源]`/`[单源]`
- **分析句** → 以 `分析：` 开头，不挂来源，但要说清推理依据

```
❌ 2024 年后该方向已转向端到端方案。
   （读者无从知道这是文献结论还是你的判断）

✅ 2024 年后该方向已转向端到端方案 [多源: url1, url2]。
✅ 分析：把上面三条路线放在一起看，2024 年后的工作集中解决 X，
   这可能是因为 Y 的成熟降低了 Z 的成本。依据：<已核实的 A 与 B>。
```

## 7. 局限声明的写法

每份报告开头必须有一段**诚实的局限声明**，至少覆盖：

- 检索的时间窗与截止日期
- 覆盖了哪些数据库/来源，**没覆盖**哪些（例如没查中文 CNKI、没查专利）
- 关键词矩阵的已知盲区（例如某子方向用了完全不同的术语，可能整块遗漏）
- 哪些结论是低置信度的

这段不是免责声明，而是给用户的**可信度地图**——他据此知道哪些地方该自己再查一遍。

## 8. 数量上限（防发散）

| 项目 | 上限 |
|---|---|
| 侦查线 | 6 |
| 每条线候选条目 | 8 |
| 进入核验的条目 | 候选 ≤24 全核；>24 取 24–32（里程碑优先） |
| 报告篇幅 | 12000 字 |
| 代表成果 | 25 条 |
| 知识地图节点 | 40 个（超了把前沿层合并） |
| 方向卡片（`07`） | 6–8 张（超过说明没排序，不是发现多） |

超了就是边界没定好，回去做 Phase 0，而不是继续加检索。

## 9. 检索通道优先级（别把时间花在最难的通道上）

| 优先级 | 通道 | 稳定度 | 适合拿什么 |
|---|---|---|---|
| 1 | **Crossref API** `api.crossref.org/works/<DOI>` | 很高 | 题名、作者、卷期页、**部分期刊的完整 JATS 摘要**、参考文献表 |
| 1 | **OpenAlex** `api.openalex.org/works/doi:<DOI>` | 很高 | 结构化摘要、被引数、作者与单位 |
| 1 | **arXiv API / abs 页**、**PubMed / Europe PMC** | 高 | 预印本全文、摘要、PMID |
| 2 | 期刊官网摘要页、机构仓储、会议 proceedings | 中 | 摘要、日期、基金、**作者单位** |
| 3 | 官方代码仓库、课程页、标准组织页 | 中 | 方法细节、参数、条款 |
| 4 | 出版商全文页（ScienceDirect / Optica / SPIE / MDPI / IEEE / ACS / Wiley） | **低** | 常 403 / 418 / Cloudflare / WAF 误判 |
| 5 | 中文库（CNKI / 维普 / 万方 / opticsjournal / researching.cn） | **低** | 多需登录或返回 406/412 空壳 |

**规则**：
- **先用 1 级拿元数据与摘要，再决定要不要为 1–2 篇关键文献去啃 4 级。**
- 4/5 级失败**不是"不存在"的证据**，只能记为"检索盲区"。
- **有校内网的用户能拿到 agent 拿不到的东西**——把中文库、付费墙全文这一项
  **明确派给用户**，并告诉他具体要哪几篇（列出 DOI/标题），这比自己硬撞有效得多。
- 每轮结束后把"哪些通道可用/被拦"写进 `00-定界与计划.md`，下一轮不再重复试错。

## 10. 止损与收敛规则

技能最容易失控的地方是"越查越多"。四条硬规则：

1. **核验失败率 > 1/3 → 停。** 说明不是文献质量差，而是**关键词矩阵或通道选错了**。
   回去重做 Phase 0 的这两项，不要继续核验。
2. **同一条线连续两次检索无新命中 → 换词，不换线。** 换线通常意味着边界没定好。
3. **一个事实出现三个以上独立来源 → 停止继续验证它。** 收益已经饱和。
4. **报告篇幅超上限 → 砍"背景铺垫"，不砍"分歧点、口径、局限"。**
   前者读者自己能补，后者只有你能给。

**判断"该停了"的信号**：新增检索回来的内容，80% 你已经知道——这时覆盖面已经够了，
应该转到 Phase 3 写和 Phase 2 核验，而不是继续扫。
